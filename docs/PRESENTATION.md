# Premove presentation guide

## Opening — 20 seconds

“Premove is a tactics game where both players plan before either side moves. You choose a team, set a sequence of moves and attacks, and lock it in. Both sides then act together. The challenge is predicting where your opponent will be.”

## Live demo — about two minutes

1. Open **Practice** and select a small party. Explain that Knight, Mage, and Archer offer different attacks.
2. Place a fighter on a safe tile. Point out walls and fatal terrain.
3. Press **A** and pause on the movement preview. Press **Enter**, then **W → Enter** to queue a left-then-up route. Explain that WASD selects movement while arrow keys aim skills. Add an attack and confirm it.
4. End the sequence with **0**, complete the other fighters' plans, and lock with **Space**.
5. Choose a fighter if prompted and resolve. Explain that movement happens before attacks, so positioning can turn a hit into a miss.
6. Show the updated health and positions. Explain that these carry into the next planning cycle.
7. Mention couch multiplayer, LAN, and the four team perks.

## Closing — 15 seconds

“The core mechanic is simultaneous planning: both players commit before seeing the outcome. Positioning, cooldowns, and team perks give each new plan a different set of decisions.”

## Before presenting

- Run the build and smoke checks from the development notes.
- Open the game and confirm that music and effects are at a suitable level.
- Start a practice match once to check the display and controls.
- Keep [the gameplay recording](../assets/presentation/premove-demo.mp4) available locally as a fallback. It is a real-time screen recording with game audio, animated key prompts, and explicit movement instructions.
- For a LAN demonstration, test both computers and the host firewall beforehand.

## Media provenance

The bundled screens use the repository's `--capture-menu` preview scenario. It constructs representative match states rather than recording a complete human-played match. Transient phase announcement cards were omitted in a temporary capture build so the board is visible. No characters or gameplay effects were generated for the screenshots.

The README GIF combines movement-planning and execution excerpts from the MP4 at their original speed. The recording uses scripted keyboard and mouse input through the ordinary game interface; it does not alter combat rules, animation speed, or game state.
